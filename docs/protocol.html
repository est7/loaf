State Machine — 3 ceremony preset 视图 rev 4.3

rev 4.2 注:Profile enum 砍掉,改 Ceremony 6 flag schema + skill PRESETS 表。本节展示的 quick / standard / deep 是 loaf-skill v1 提供的 3 个默认 preset(skill 维护映射 preset 名 → Ceremony object),不是协议层 enum。3rd-party skill 可起任意 preset 名。各 preset 的 ceremony flag 配置见 protocol.md §3 表 / schemas.ts::Ceremony schema。

3 个 preset 状态机骨架(由 ceremony flag 决定哪些 phase 跑):quick = ceremony 6 flag 全 false → 3 phase(TRIAGE/EXECUTE/DONE);standard = ceremony.{spec/verify/settle}_phase 全 true → 全 6 phase + 2 human gate;deep = standard + ceremony.strict_* 全 true(4 enforcement extras)。

① Quick profile(TRIAGE → EXECUTE → DONE,跳 SPEC / VERIFY / SETTLE)

quick 特征:无 human gate,无 back-edge(quick 不允许 finding),无 SPEC.* / VERIFY.* / SETTLE.* sub-state。verify-min 在 EXECUTE.done → DONE.delivered 边线上跑(`loaf deliver` 入口);spike + quick → deliver hard block,用户显式 archive / spike convert / abandon。fan-out 在 EXECUTE.work 仍生效(worker 并发);pending FIFO 队列任何 phase 可 raise。

② Standard profile(全 6 phase + 2 human gate)

Q9 backfill 路径(rev 3.1):quick→standard 升级时,从 EXECUTE 回跳到 SPEC.proposal,带 spec-draft-context.md 让 loaf-skill 反向归纳 spec。复用 SPEC.proposal,不新增 sub-state。

spike 在 state machine 上不直跳 DONE。verify-min 仅 hard-block loaf deliver;用户必须显式跑 loaf archive --reason "..." / loaf spike convert --to-feature F-N / loaf abandon --reason "..." 三选一(§8.3)。这三个命令是 session 终结命令,可在任意 sub-state 调用 → DONE.archived 或 DONE.abandoned,但是用户显式触发,不是 state-machine forward edge,故 SVG 不画。

两条正交于 state machine 主轴的 v1.0 语义

⚡ Worker fan-out(rev 4.0)

EXECUTE.work sub_state 是唯一 worker phase,允许 sub-agent fan-out 并发。Active set = tasks.json.tasks.status="in_progress" filter(多元集合);其它 sub_state 全是 control phase,主 skill serial 跑。

Fan-out 不影响 state machine 主轴 — state.json 仍是单 cursor;active set detail 走 tasks.json(SSOT)。详见 references/loaf-skill-helpers.md §4。

⏸ Pending FIFO queue(rev 4.1)

state.pending: PendingPromptEntry[](default [])。任何 phase 都可能 raise pending(gate_decision / finding_decision / profile_escalation / spec_clarification / ask_user_question),append 到队列尾。

Head 阻塞 user-facing 命令,不阻塞 worker — worker 继续跑自己的 task 直到自己撞 pending;只有 user 答完 head 后队列下一个 promote 为新 head。FIFO 严格,resolve 永远 pop head(v1.0 无 --id 跳序)。

两条语义都属于"side channel" — 不修改 phase / sub_state cursor;主 state machine 图仍清晰 readable。

③ Deep profile = Standard + 4 enforcement extras(overlay,无新 sub-state)

Deep state machine shape 100% 等同 standard(无新 phase / sub-state / gate)。差别全在 policy 严。机器表达见 schemas.ts::PROFILE_POLICIES.deep。

🔒 spec-reviewer required
@ spec-lock gate
额外校验:存在 kind=spec-review evidence 且 actor ≠ implementer;否则 gate 阻断
schema: spec_reviewer_required: true
👀 actor ≠ implementer enforced
@ VERIFY.review
verify-review evidence 的 actor 字段必须跟该 task 的 implement step 的 actor 不同;deep gate-time enforce
见 §5.2 verify-accept 第 5 条
📖 lessons.md MUST
@ SETTLE.lessons
lessons.md 必须 append ≥1 段(`## F-XXX feature-name · date (iterations=N)` 起头);standard 是 MAY,quick skip
schema: artifacts_required ⊇ ["lessons.md"]
🔬 strict drift-check
@ SETTLE.reconcile

见 §4.6 reconcile.json 字段

Deep 实际跑跟 standard 看起来一模一样的 state machine — sub-state 序列 / gate 数量 / back-edge 结构全相同;只是 4 个 enforcement 检查在 gate 时间更严。这就是 ADR-0002 「protocol manages shape, profile manages policy」原则的延续。
